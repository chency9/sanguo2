# 战场兵员间距修复 · 2026-11-17

用户反馈百人列阵时士兵紧贴，身体被相邻行列遮住。旧代码列距为 24、排距为 31（方阵 22），步兵和骑马主将统一使用 0.64 缩放。以刀兵一个 76×96 源帧为例，显示约 49×61，明显大于阵列间距。行进避让仅对距离小于 10 的部分友军生效，攻击中的士兵不参与，索敌后还会再次拥挤。

## 改动

- 横列阵和锥形阵列距 40、排距 40，奇偶行错开 20；方阵列距 40、排距 36，居中排列。阵形仍是不同站位，不删减实际兵数。
- 步兵源图统一等比缩放到 0.50，骑马主将保留 0.64。源动画、锚点、蓝红配色及按脚点排序继续使用。
- 主将后移到阵列后方。原布阵和主将位置改变也会影响接敌、撤退所需时间，不能将此视为纯装饰修改。
- 每个固定模拟步结束，使用三轮稳定顺序的友军分离处理。步兵足点间采用 32×36 椭圆间距，含主将时为 44×40；攻击中的单位也参与。待命者不会被推进的友军推走，完全重合时使用确定方向，不引入随机数。
- 预备兵按十条入口逐个检查占用。拥堵入口推迟补兵，只有实际进入的士兵才从预备兵扣除，计数保持守恒。

上述值是可读性与交战行为的暂定 Web 参数，未与原 EXE 运行画面逐帧测量。不承诺攻击动作的武器完全不交叠；双方肉搏仍会接近。

## 存档与使用

刷新页面并重新进入「演武场」可查看新列阵。已有战中存档保留坐标、动作和时钟，恢复战斗后使用新的避让规则；已有列阵存档可以重新选择阵形来重排我军。旧存档不会自动跳转到新的初始坐标，新规则下的后续战果可能与旧版本不同。

## 验证

先运行 `pnpm exec vitest run packages/core/src/battle.test.ts -t 'visible space'`，旧版三种百人阵形全部失败；修复后通过。新增近战/远程敌军下的持续拥挤检查、完全重合解开且待命者不动、入口被士兵或主将占用时的补兵守恒测试。每侧仍可同时部署 100 个真实士兵。

38 项核心测试、17 项 Chromium E2E 通过，类型检查和生产构建通过。浏览器回归覆盖 1920×1080、1440×900、1024×768、844×390、390×844、320×568；实机查看 1440×900 的列阵、弓箭接敌和混战截图。
