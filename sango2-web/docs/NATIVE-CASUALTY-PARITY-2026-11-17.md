# 死亡随机调用与战术网格对照

本轮修复两类会改变后续AI输入或随机结果的遗漏：死亡时跳过的随机调用，以及战术查询使用55列、忽略主将的临时网格。**局部函数已对照，完整战斗、全局随机顺序和逐帧画面仍未达到一比一。**

后续进展：新战斗已接入目标格预约和定点移动，死亡输入也改为读取预约格及模拟坐标。本文下方“连续坐标投影”的描述保留为本轮历史状态；当前实现和剩余调度差距以[移动对照](NATIVE-MOVEMENT-PARITY-2026-11-17.md)为准。

## 原程序证据

基准EXE SHA256：`1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`。

| 原版函数 | 已核实并接入的规则 |
|---|---|
| `0x43DB0D` / `0x43DA1A` | 士兵死亡清除占格并减人数；预备兵按兵种/左右阵营创建脱离对象。第6行额外抽取`below(0x200000)-0x100000`作为方向偏移 |
| `0x406569` / `0x406444` | 脱离对象编号与骑乘标志是两种不同查询；不能用同一个布尔值替代 |
| `0x43DC56` / `0x43BE42` | 根据攻击者左右位置确定击飞方向；依次抽取横向48、纵向36、竖向65536三个随机值。平面速度有120/90源像素位移限幅，再除80向零取整 |
| `0x43DC56` | 普通兵起跳速度`0x40000+随机`，预备兵`0x30000+随机`；高度先加32源像素，骑乘预备兵再加34。武将死亡的上游`0x43DB9A`先加54 |
| `0x43CD48` | 16.16定点坐标运动；先加速度到位置，再施加20480竖直减量，穿过地面后高度/竖速清零；动作8暂停这段运动 |
| `0x43E1C7` / `0x4224C1` | 脱离坐骑初始化寿命2400源更新；`OM_WALK`抽取4–7速度，再用原角度常量`3.1415926`计算平面速度 |

| `0x402920` | 含端点矩形，反向端点先交换；只统计每格最终占用者所属阵营，包含主将，不是只数士兵 |

原始脱离映射还存在一个不对称分支：某些非骑乘兵种左侧编号为0，右侧返回0+10。THINGS中的对象10是旗帜。本轮保留该函数输出和不产生坐骑奔跑抽签的行为，没有自行改成对称规则；它还需要原客户端实机对应场景复核。

## 可复现对照

运行`web-port-research/tools/native_casualty_oracle.py`，使用已有`.venv-ai`。测试执行原机器码及原内部调用，包括对象分配、原对象处理回调、原随机函数、三角函数和网格查询；不替换游戏或随机函数。**唯一OS替身是固定返回0的GetTickCount**，用于对象创建时间戳。对象池、动作链和战场状态为构造的内存快照，并非读取一次完整原版战斗。

输出`web-port-research/evidence/ai/native-casualty-vectors.json`，同步到核心fixtures：

- 416组死亡初始化，涵盖13兵种、现役/预备、主将、左右阵营、攻击者有无及位置、中线方向偏移；核对定点速度、高度、脱离对象、最终随机状态。
- 128组多次定点运动，覆盖重力、地面、暂停动作和标志分支。
- 104组脱离坐骑奔跑，核对速度和随机状态。
- 200组网格查询，覆盖重复占格、矩形倒序和越界端点。
- 13组兵种对象映射。

共861组原函数结果。另有边界和生命周期回归：死亡只消费一次、延迟事件在第24次源更新触发、事件前存读档一致、旧档继续旧随机计划、损坏数据拒绝、脱离对象到期不改变兵数，以及军令不得把已死单位改成撤退行走。

## Web接入与兼容

- 新战斗带`casualtyRules: native-v1`；没有该字段的旧战中存档保留旧网格输入及原随机调用，继续既有战斗，不在载入时重骰。新轮次采用新规则。
- `battle-casualties.ts`保管定点击飞状态、脱离对象年龄和延迟事件；这些都存入快照。Canvas只读位置，重绘、屏幕刷新率和窗口缩放不会消费随机数。
- 坐骑WAIT在原THINGS配置中是两个12更新帧后`OM_WALK`。Web按24次源更新触发奔跑抽签，在既有每步3更新框架内推进；与AI/命中共用随机状态。
- 补出12个脱离坐骑对象及对象10；资源总计227个对象、5226张源帧。渲染预载当前兵种所需素材，并支持直接读取已有脱离对象的战中存档。
- 战术输入使用71×14占格查询，主将参与阵营计数。小地图与AI共用`projectBattleCell`，避免同一位置被两处解释成不同格。
- 战场士兵伤亡和脱离对象分开统计；空坐骑/旗帜不会增加场上兵力、成为攻击目标或占用AI格子。

## 仍有明确差距

1. **占格来源仍是连续坐标投影。** 原版预约格、移动完成、前后位置字段、7×7影响权重及全局链表顺序未接入。连续坐标映射到同格时，当前按Web单位数组顺序保留最后一个，不冒充原版移动分配。
2. **完整调度仍有差距。** 3次源更新成组推进；死亡/坐骑事件、AI与其他单位的跨对象执行顺序不是原版全局对象链表。飞行抽签和延迟抽签已补，不能据此宣称完整战斗随机流对齐。
3. **死亡动画只接入起跳和定点飞行阶段。** 着地后原版强制跳帧、反弹、尸体渐隐和最终移除事件尚未完整实现；Web暂保留旧尸体显示寿命和淡出适配。战斗结束即停下模拟也仍是Web行为。
4. 原版飞行坐标到当前Web战场采用明确缩放适配，未完成原相机/透视逐帧对照。射箭落地/弹飞还另有随机调用未接入。
5. 五分队命令、完整武将技、其他军师技、AI对AI战斗结算、战略链表与同一SAV整局回放仍待完成。
