# 军师决策与战役输入修正（2026-11-17）

本次延续原机器码差分验证。军师选择和下述已验证效果现已接入游戏，仍不代表全部军师技或全局 AI 一比一完成。

## 实际接入 Web 的修正

- 部队入城、战后返回及守城结算，若将领现有兵数与城市总数一致，保留每将的兵数。此前会无条件平均分配，改变下一次战术评分、出阵抽签与战略出征资格。
- 开战保留原分兵，包括不能出阵的重伤武将及其兵力；不把这些兵免费平均转交给其他将领。无可出阵武将时，现有 Web 守城校尉兜底仍存在，并明确不是原版行为。
- 守城队伍不再按武力重排。按当前城市链表适配顺序建立队伍，并参考 `0x446B52` 将在场太守交换到首位。原出阵函数 `0x403D2F` 对首槽设权重上限 10；错误排序会保护错误的武将。
- `0x468740` 抽签的余数按有符号 int32 比较，逐次减法也保留 int32 溢出。通常的小正数权重结果不变；新增机器码样本覆盖负数、总和回绕和符号位边界。

城市列表仍采用源数据倒序的既有适配，太守来自剧本且须当前在城。动态太守任免及完整链表增删顺序尚未恢复，不能把本次交换首槽称为完整名单还原。无法对齐的旧存档/未分配守军总数仍使用显式平均分配兜底。

`native-strategy-effects.ts` 中的支持表只包含已经追到 `0x44D450` 分派和 `0x43E847` 恢复逻辑的 EXECUTE。战斗中恢复每个原始更新累积一次，严格在累计值大于 6000 时恢复一点；战阵结束会把临时上限恢复到入场值。状态写入 `BattleState.strategies`，经过存档校验，没有军师状态的旧战斗存档保留原行为，不在开战时补抽敌方计策；玩家明确选择计策后才添加状态。

## 新发现：Rate 与 Level 不一致

游戏包中的 EXE 与差分基准 SHA256 相同：

`1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`

`0x42F862` 加载的字符串位于 `0x48CC58`，原字节为 `52 61 74 65 00`（`Rate`）。原加载器在 `0x42F86E` 请求此字段，忽略返回状态，然后将栈局部 `var_8` 写入军师表权重。提取的 `MAGIC.INI` 对应字段却是 `Level`。

`0x45568D → 0x455187 → 0x45509F` 按忽略大小写的完整键名查找，查不到时返回失败且不写输出。直接执行原查询机器码，对只含 `Level=120` 的合成解析器表查询 `Rate`，四个输出初值 `0 / 120 / -1 / 0x12345678` 均原样保留，返回值均为 `0xffffffff`。这不是根据技能名称推测的规则。

因此，静态加载路径存在未初始化权重输入。通过三次独立、无文件修改的受控启动采集到 `*(0x4A61A8) + 24*sequence + 12 == 4214897`（67 个技能全部一致），该值等于 `0x405071` 初始化调用返回地址。Web 已使用这个运行时值，不再把配置 Level 冒充 Rate；采样记录见 `runtime-strategist-1/2/3.json`。这仍是该启动环境的证据，不能替代从每个原存档连续运行的全局 RNG 回放。

已接通上述恢复、集气和封技效果。后续已接入强化/削弱士兵、双向战力增减和强将命中加值，见[普攻与强化对照](NATIVE-COMBAT-PARITY-2026-11-17.md)；又接入士气、疲劳和离间，见[人物状态对照](NATIVE-CONDITION-PARITY-2026-11-17.md)。劝降、经验、特殊布阵等未实现分派仍待接入，不能把选择内核或部分效果通过称为全部军师技完成。
