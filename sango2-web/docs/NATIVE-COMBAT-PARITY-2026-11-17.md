# 普攻、克制与强化军师技对照（2026-11-17）

已用原 EXE 机器码替换 Web 普攻的必命中及浮动估算伤害，接入兵种/地形克制、可映射阵形克制、守城城防和强化类军师技。**这是给定输入的函数等价，不是整场战斗或整个游戏一比一完成。**

## 随机数和保存

普攻命中及伤害现在直接消费 `BattleState.opponentAI.rng`，与战术、技能、选将抽签共享两个 uint32 状态。原先普攻专用的 xorshift 已移除；命中失败、普通兵受击和随机范围为零时不会额外抽伤害随机数。战后沿现有回写路径返回战役随机状态。

新状态包括军师 `soldierPower` / `generalHitBonus`、兵员 `nativeReserve` 和战场 `fortifications`。读取旧存档时，缺失值分别解释为 150/0、普通兵、无城防；不会重新抽取旧战场军师技，也不会在战中补施之前标为 pending 的计策。旧存档仍可继续，但升级后的后续普攻采用本次核实规则，**不承诺与旧 Web 版本战果相同**。同一新版本存读档的后续模拟逐字段一致。

## 必须继续闭合的差距

- 当前仍是连续坐标和每步三次原更新的适配；原版“已到目标格”暂以 Web 动作为 walk 与否表示。攻击触发顺序、移动/碰撞、弹道飞行与落点均可能改变命中时刻及 RNG 消耗。
- Web 仍按最多 100 兵首批出场，再从场外补兵；当前场外预备标记不等于原版现役/预备的完整初始化、同时布阵与容量规则。旧战场无法补推每个兵的原始类型。
- 兵种与地形表已使用，但战役城池/道路尚未自动选择原地形。演武所选地形会影响实际战力。
- 玩家“方形/锥形”映射为原索引 0/2；现有“横列阵”尚无已核实原版映射，阵形加成明确使用 0。敌方使用原抽签阵形索引，但可见站位仍未恢复全套原阵形。纯函数完整支持 11×11 表，不代表界面已有 11 阵。
- 后续已接入战役士气、驻城疲劳/忠诚、战后疲劳、临时士气恢复和离间，见[人物状态对照](NATIVE-CONDITION-PARITY-2026-11-17.md)。新战斗不再固定使用士气 50；劝降、经验和其他技能仍待恢复。不得把部分效果接入称为全部军师技完成。
- 电脑双方仍是估算自动结算，没有通过本实时战斗链。仍缺从同一原存档、同一操作连续运行的客户端/Web 双轨回放。
