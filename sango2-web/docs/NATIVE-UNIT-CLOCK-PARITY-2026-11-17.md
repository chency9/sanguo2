# 单位源更新时钟与攻击搜索对照

新战斗使用 `movementRules: native-grid-v3`：每个 Web 步内部按三次源更新依次执行单位，单位决策、攻击搜索、运动和友军递归更新共享当次源时刻。v1/v2 及无标记的旧战中快照继续各自旧规则，不在读档时重算随机结果。

**这不代表整个游戏事件系统已逐帧一致。** 全局战术 AI、军师恢复、集气、死亡/坐骑事件仍由外层按三次更新成组推进；原对象链表顺序、全部动作消息、技能和箭矢系统尚未接齐。

## 原规则与机器码证据

基准 EXE SHA256：`1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`。

| 地址 | 核实并实现的规则 |
|---|---|
| `0x43B574` | 每次单位源更新先递减决策计数。大于零不决策；到期普通单位重置 40，撤退重置 46，主将撤退加 `2*(敌速度-己速度)`，不擅自钳制负结果 |
| `0x43DDBF` / `0x43EF64` 消息 65549 | 决策到期若有延迟计数，将它写入决策计数，清掉延迟，停止运动并返回“不决策”；对象缺失分支保留原返回 |
| `0x43BCA7` | 仅在决策时递减攻击搜索冷却。冷却仍大于零则不查敌、不抽随机数；普通单位抽原随机函数最低位决定先查方向，失败后反向；撤退只查当前朝向，不抽方向 |
| `0x43BBE6` / `0x43B961` | 沿同一行扫描，活友军阻挡后方敌人；按主将、兵种、现役/预备原射程表读取范围 |
| `0x43D125` | 找到目标后，近战抽 `below(8)` 决定特殊攻击；远程以目标是否相邻选择特殊动作，然后检查撤退攻击限制。抽签发生在限制检查之前 |
| `0x406717` | 读取 13 兵种、现役/预备、普通/特殊攻击冷却四列原表，不能用动画时长代替 |
| `0x43E964` | 主将找到可攻击目标后将攻击搜索冷却置 1，不消费士兵的近战特殊攻击抽签 |
| `0x43CCE3` / `0x43C1E7` | 开始攻击时把事件定点坐标移到本格中心并清零速度 |
| `0x43D686` / `0x43D76C` | 命中事件重新读取前方相邻格；主将可命中空邻格后第二格的撤退主将。前方活友军阻挡；原士兵特殊近战分支绕过普通命中抽签 |

原普通移动决策在源更新 1、41、81……发生。决策所在更新设置速度，其他更新才积分，因此首次两次决策之间有 39 次运动积分。v2 先积满 40 次再等 Web 组边界的行为不再用于 v3。撤退仍用除以 40 计算速度，但决策时钟是 46；不将速度除数也改成 46。

## 可复现原函数对照

在 `web-port-research` 目录执行：

```powershell
& .venv-ai/Scripts/python.exe tools/native_unit_clock_oracle.py
```

输出 `evidence/ai/native-unit-clock-vectors.json` 并复制到 Web 核心 fixtures，同时从 EXE 导出 `native-attack-cooldowns.json`。

- 240 组决策时钟：负/零/边界计数、延迟、对象有无、普通/撤退/主将和双方速度差；执行原 `0x43B574` 及真实延迟回调。
- 390 组攻击搜索：13 兵种、主将、现役/预备、冷却、左右朝向、撤退、友军/死亡阻挡、场边；核对带符号目标距离、冷却值和最终双字 RNG。
- 52 组冷却表：13×2×2 原函数返回值。
- 312 组完整士兵决策分支：执行原 `0x43D125`、真实士兵回调与内部移动/索敌/随机函数，观察攻击消息、普通/特殊动作选择、计数和 RNG；目标缺失时使用原待命命令。

合计 **994 组**。没有替换原游戏或随机函数，无 OS API 替身。完整分支夹具使用构造的动作资源、单行敌人与待命命令，未执行原弹道或完整战场，不声称它覆盖所有原游戏状态。

## Web 接入、存档与显示

- `native-unit-clock.ts` 保存原决策/搜索/攻击准备规则；`battle-unit-scheduler.ts` 按每次源更新调度单位，并通过现有损伤/死亡接口结算。
- 单位保存 `decision`、`attack`、`deferred`、`actionAge`、`special`，以及每次源更新的 `updatedAt`。递归让路和正常轮询不会在同一源时刻重复处理同一单位。
- 友军让路中的旧 v2 回归继续保留；v3 的段中保存、命中前保存与恢复另有测试。旧命中/死亡抽签夹具明确标为 v2，验证兼容；v3 也测试了真实伤害和尸体创建。
- 攻击搜索采用预约格，不再使用人物显示距离。命中时重新查格，近战目标离开后不会隔空受伤。远程发射与伤害仍走下述兼容适配。
- 新军令只改变命令，等单位下次决策处理；不重置正在进行的攻击动画、目标或决策计时。旧规则维持原处理方式。
- 非死亡动画读取保存的源 `actionAge`，不再把源年龄先向下取整到三个更新的倍数。尸体淡出继续旧生命周期。
- 运动使用增量推进显示位置，保留已有间距偏移；偏移不反写预约格或定点坐标。边界上的显示校正可向场内让出位置，避免校正又被边界钳制抹掉。百人和满编可辨间距继续回归。
- v3 存档校验计数、源年龄及特殊动作标志，拒绝缺失或损坏时钟。版本切换仅发生在新战斗/新轮次，不修改旧战中快照。

## 仍待完成的差距

1. **主将速度未接入数据转换。** 纯函数的原速度差分支已有对照，但运行输入暂用双方速度相同（均为 0），主将撤退实际仍按 46。未虚构各武将速度；需要继续核实初始化/装备对该字段的写入。
2. **全局调度仍成组。** 单位内部逐源更新已实现，但 AI、技能、集气、军师恢复、死亡/脱离对象与单位之间的跨对象顺序不是原全局链表。不能据此宣称整场 RNG 流一致。
3. **特殊动作动画与事件。** 本文编写时特殊攻击仍借用普通动作。2026-11-18 已补齐 `WIN` 特殊攻击素材与原解析器/步进器核实的命中帧，见[攻击动作对照](NATIVE-ATTACK-ANIMATION-PARITY-2026-11-18.md)。完整非攻击帧消息、主将连击等仍未接入。
4. **普通投射物已接入，技能弹道仍缺。** 新战斗中相邻格为空且原兵种射程大于 1 时，按原四类对象创建投射物，逐源更新飞行并重新查询沿途格；命中、友军拦截、偏转随机数和飞行中存档已有单独对照。武将技投射物、全局混合对象链表顺序和完整受击消息仍待补齐，详见[远程弹道对照](NATIVE-PROJECTILE-PARITY-2026-11-18.md)。
5. **命令与初始计数。** 三种 Web 命令仍映射到追击/待命/撤退，未完成原十命令、五分队、7×7 影响网格和原布阵。新单位从 `decision=1, attack=0, deferred=0` 开始，这是显式初始化适配，尚需原入场创建链对照。退场仍沿用上一轮的 40 更新结束适配，原 64 次淡出消息未接齐。
6. **画面空间。** Web 1200 宽战场和精灵间距仍是显示适配。攻击按原格，人物显示可能受防重叠偏移影响，需要后续原屏幕坐标/透视校准。

## 验证

核心 **7,634 项 / 22 文件通过**。包括新增 994 组原函数结果、9 项源调度运行回归，以及同时检查 v2/v3 攻击事件时点的兼容回归。验证普通源更新 41 重新决策、撤退源更新 47 重新决策、搜索冷却只在决策时递减、被友军阻挡仍按原顺序消费方向抽签、命中前 JSON 重放、延迟等待、军令不重置攻击、近战目标移开不受伤和满编间距。

浏览器 31 场景通过，含桌面/手机 400 人战斗、暂停、撤退、轮战、存读档及 24 地形；类型检查和生产构建通过。最后渲染源年龄与攻击反馈接点调整后，相关 985 项核心测试、4 个浏览器场景、类型检查与构建再次通过。25369 开发服务返回 HTTP 200；最新桌面/手机截图为 `screenshots/native-troops-combat-1440.png` 和 `screenshots/native-troops-combat-390.png`。
