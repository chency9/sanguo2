# 敌方 AI 与玩家守城闭环

**历史记录：下述暂定策略已被后续移植替换。当前实现、原机器码验证和未闭合差距见[原版 AI 决策内核](NATIVE-AI-PARITY-2026-11-17.md)。**

2026-11-17：敌方已能在战略图主动行动，并触发玩家守城。此次实现是可运行、可保存、可重复验证的 Web AI；不是已经恢复的原版完整决策算法。

## 战略决策

每推进五个战略日，各电脑势力进行一次决策。默认日期从一月一日推进至一月六日即可观察第一轮行动。暂停日历时 AI 不自行推进，玩家战斗期间冻结战略日历。

- 内政与玩家共用命令校验和实际资源扣除。驻将兵力不足每将 100 人时，优先花 200 金、50 人口征募 50 人；金钱至少 600 时才考虑花 300 金开发。仍受每城每天一次内政限制。
- 每势力最多同时维持两支行军军团。出征将领体力至少为最大值的 40%，最多五将，单将最多配 100 兵；出征至少 40 兵，最多带走城内约 65% 兵力。有多名驻将时尽量保留将领，有敌军来袭的城市不向外派兵。
- 沿已开放道路行动，使用实际道路行军时长。优先占据无主城市，对有主邻城仅在估算战力达到对方 1.25 倍时考虑进攻；同势力避免重复出发点和目标。
- 通过己方道路寻找受威胁城市或前线城市，向兵力较少的城池逐段增援，救援优先级高于普通扩张。
- 决策排序固定，不额外引入随机数；相同状态保存、恢复后仍产生相同决策。

上述阈值集中在 `packages/core/src/strategic-ai.ts`，均为明确的 Web 暂定策略。战力估算为 `(兵数 + 将领数 × 25) × (0.6 + 平均武力 / 100)`，尚未纳入原版兵种相克、城防、军师技和技能组合。

## 敌军来袭与结算

地图增加来袭提示，显示势力、目的地、兵力和剩余天数，点击可定位目标城池。行军列表和地图旗帜显示实际势力。

玩家遭到进攻时进入实时守城战斗。玩家始终控制左侧部队；内部历史字段 `attacker` 继续表示左侧战术槽位，新增 `invasionSide` 单独记录战略进攻方。超时、逐将轮战、保存恢复和战后回写均使用真实攻守角色；守城玩家不会因超时被误判为进攻失败。旧存档未带该字段时仍按原来的左侧进攻解释。

战斗结束后只结算一次，按真实双方记录伤亡、城池归属和战报。败退军团只有在出发城仍属本势力时才能回原城，否则转入其他己方城市；势力已无城时将领转为在野，不把败军兵力送入敌城。全体驻将受伤时允许临时守军参战，这是 Web 兜底规则。

电脑之间的战争采用有界自动结算，不打断玩家：较强方获胜，败方余兵为原兵力的 20%，胜方损失比例为 `min(0.65, 0.15 + 0.5 × 弱方战力 / 强方战力)`；双方将领体力分别损失 15% / 50%。该公式是 Web 近似，未宣称来自原 EXE。

## 战场 AI 与原版证据

战场敌将定期判断体力、兵力和施法条件。已学会且可负担命疗术、集气满足条件、至少缺少 20 体力时才能自疗；使用与玩家一致的技能门槛和技力扣除。体力不超过 20% 且兵力劣势时下令撤退，并停止继续投入预备兵。未实现的技能仍禁用。

相邻 `web-port-research/evidence/ida/static-export/00402ea5.c` 的原生战术决策读取体力比例、兵力比例、可施法状态、八个已学技能和技力；`timer-dispatch.json` 中 `00444385` 提供对手决策定时分派证据。源程序指纹为 `1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`。

这些证据支持决策输入与调度研究，不能证明本轮战略权重、撤退门槛或自动结算公式与原版一致。原版完整技能选择、战略调度、搜索登用、外交、俘虏、成长、疗伤和统一结局仍需继续恢复。
