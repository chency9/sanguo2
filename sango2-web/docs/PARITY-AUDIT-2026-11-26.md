## 前几轮进度说明需要纠正的地方

1. **电脑互战尚非双方原版 AI。** `resolveRivalEncounter()` 复用了战场步进，但进攻方默认选首个可用将，每阵固定下达全军前进；`decideOpponent()` 仅控制守方的选技、军令和撤退。进攻方并未获得同样的战术决策。电脑路径的 `rivalCommander()` 也没有使用玩家路径的完整 `officerDefinition()` 外观/装备适配，战后未像玩家路径一样写回士气、疲劳和忠诚。[战役代码](../packages/core/src/index.ts) · [战术 AI](../packages/core/src/battle.ts) · [军师选择](../packages/core/src/battle-strategies.ts)

2. **道路相遇战没有接入游戏。** `roadMidpointTerrainForDay()` 和 `strategicEncounterPosition()` 只有定义与测试调用。真实战役仍在 `arrivals()` 中筛选 `remainingDays === 0` 后触发城战；两军在路上不会因为这两个函数自动交战。最近两次坐标提交属于基础整理，不能当作已经恢复中途遭遇。[核心入口](../packages/core/src/index.ts) · [地图实际使用的投影](../apps/game/src/WorldMap.tsx)

3. **年度经验追赶缺少实战来源。** `policy.annual.battleExperience` 初始化为 0，之后只有读取和校验；玩家与电脑战后路径都没有逐将战功/经验授予。年度算法存在，输入链仍不完整。[年度处理](../packages/core/src/native-policy-annual.ts) · [战后写回](../packages/core/src/index.ts)

4. **MAPMODE 仅有内容字段边界。** 当前 `battleSceneryMode` 支持固定 A、固定 B 和随机选择，并非已经复刻命令行 `-MAPMODE` 设置入口。季节地形也仍缺原客户端城景动态分类和连续 RNG 对照。

5. **测试数量与截图不能代表复刻比例。** 之前的 16,775 项测试和 Chromium 检查是 Web 实现的历史验证记录。现有截图主要是 Web 自身截图，尚无完整的原版同状态像素比较；本次不把历史通过数写成重新验证通过。

## 后续开发优先级

1. 打通战后逐将经验、势力累计经验、俘虏和归属处理，随后完成继承、灭亡与结局。
2. 将电脑互战双方都接入战术 AI，统一装备/兵槽/状态写回，并建立连续战役对照。
3. 逐个替换 94 个通用武将技及 15 条军师技缺失效果，恢复完整对象调度。
4. 恢复中途遭遇、原行军规则、年度人物与历史事件。
5. 建立原版逐状态 UI/字库/音效基线，补原 SAV 兼容与整局回放验收。

这些阶段都有实质性功能工作，不能用增加辅助函数或增加测试数量代替。完整范围继续由[一比一复刻总账](FULL-PARITY-BACKLOG.md)和[110 技清单](MAGIC-COVERAGE-2026-11-19.md)跟踪。
