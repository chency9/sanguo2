# 年度人物出场与亲族归附

Web 战役现已把原版年度人物变更接入跨年内政。规则读取每将的五段 `POS` 与 `BLOOD`，处理未出场人物出现、在野人物消失、亲族投奔、归附成长与满城转移。它不以出生年份或自编历史名单代替原资料。

## 原程序依据

对照程序 SHA-256 为 `1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`。静态导出保存在 `web-port-research/evidence/ida/static-export/`；原机器码采样工具为 `web-port-research/tools/native_officer_appearance_oracle.py`。

| 入口 | 规则 |
|---|---|
| `0x423020` | 年份分段为 `<187`、`187–194`、`195–204`、`205–213`、`>=214`；194、204、213 年强制处理 |
| `0x423681` | 按全局人物名单遍历；五段概率分母依次为 3、7、9、8、12；不符合状态/地点条件的人物不消耗随机数 |
| `0x4230AC / 0x4235EA` | 未出场 `8192` 且有地点才尝试出现；在野 `8` 且无地点才尝试消失；消失写为 `4096`，以后不再考虑 |
| `0x423476` | 无现驻城且有血缘人物时，须血缘人物仍在任并有所属势力；优先投奔亲属所在城，其次君主所在城，再从势力城池名单抽取 |
| `0x4230ED` | 电脑满城时转入全局城市顺序中首个可见、同属且有空位的城市；全满时仍接受原目标；玩家不作此转移 |
| `0x426B44` | 先完成归附与名单头插，再从玩家名单计算经验并升级；成长抽签在下个人物的出场抽签之前进行 |
| `0x423885` | 人物出场 → 清年度行动 → 年度电脑内政 → 税收；新归附人物不会因旧年度行动标记失去本轮内政 |

原 `0x4068EB` 在建立人物时将节点接到全局名单尾部，因此首次全局顺序使用来源资料顺序。城市和势力人物名单保留已有头插适配；同年出现的子女可以使后面的亲族满足归附条件。

## Web 接入与保存

- 转换器导出全部五个剧本的 `appearanceCities` 与 `relativeId`。
- `native-policy-appearance.ts` 在 `beginDomesticYear` 调用内核；归附即时更新人物归属、驻城、两类名单、城池兵数和成长。
- 原 `4096` 使用 `appearanceHidden: true` 保存。界面状态仍沿用“未”，随机处理另行识别隐藏状态，读档后不会重复出现。
- 玩家亲族归附写入纪事。原多人对白和 `System.SO` 表演流程尚未接入。
- 不含 `appearanceCities` 的旧内容跳过；没有原版随机状态的旧存档也跳过，不另造随机源。

## 验证

原机器码样本包含 16 条年份边界、160 条年度选择、80 条地点/亲族转换、96 条保留真实归附成长的连续年度场景，共 352 条；另有同年回调顺序测试。353 项内核测试通过。

连续场景保留原 `0x423681 → 0x423476 → 0x426B44`，替代图形对象建立与对白宿主，核对最终人物状态、城市、归属、等级、经验、HP/MP、兵数、通知顺序和共享随机数。它们包括强制年、普通概率、同年亲族链、玩家/电脑归附、满城转移，证明的是这些输入下的函数链行为。

13 项战役测试覆盖原五剧本的跨年与 JSON 读档、四次后续 POS 时段真实激活（每次 8 个种子）、同年两代亲族加入、隐藏后不重试、旧内容与旧存档边界。内核与战役 2 文件共 366 项测试通过；此前年度相关 3 文件 1,106 项测试与 TypeScript 检查通过。

尚未完成原客户端整局连续回放、`System.SO` 历史事件、原多人成年对白与窗口逐像素对照。因此，本次恢复的是年度人物规则与战役入口，不能据此宣称完整内政或整局达到一比一。
