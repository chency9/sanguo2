# 主将源更新、坐骑速度与技能镜头

日期：2026-11-19。基准为用户提供的 1.05+ 默认游戏包。

本次补齐主将集气、军师恢复的源更新位置，接入装备速度对撤退决策间隔的影响，以及四种 ShootObject 技能的 LockCamera / MoveCamera。**完整技能、混合对象链、连续 AI 回放与原版 UI 逐像素验收仍未完成。**

## 主将更新

原 EXE `0x43E964` 前段按以下优先级执行：

1. 撤退标志存在时，集气减 50；不把零以下截成零。这一分支先于死亡动作检查。
2. 非撤退且当前动作不是 32 时，按 `0x43E72E` 增加集气，上限 120000，然后调用 `0x43E847` 恢复。
3. 恢复累计器加军师参数，严格 **大于 6000** 才减 6000 并回复一点。HP 标志优先于 MP 标志；满值时仍消耗该次累计。
4. 正在施法并不是这段原码禁止恢复的条件。普通移动、索敌、攻击在这段之后执行。

`native_general_tick_oracle.py` 执行原撤退判断、动作 getter、集气倍率和恢复函数，在后续动作分派前停止。640 组输入覆盖负/零/满集气、死亡动作、撤退、军师标志与阈值；没有替换 RNG 或上述游戏函数。

新战斗保存 `generalRules: native-source-v1`。主将在实际源更新位置执行一次恢复与集气，递归让路不会重复。旧存档缺少该标记时继续原成组更新与撤退集气行为。负集气在新规则中可保存、回放，旧规则仍拒绝负值。

## 装备速度与撤退

原链路为 `0x4067B0` 清零人物内存 → `0x42D1A3` 加载武器、坐骑和物品 → `0x4088FA` 按等级应用物品 SPEED → `0x4429FD` 读取人物 `+64` 的有符号 16 位速度。

`native_general_speed_oracle.py` 用原 `0x4088FA` 生成 698 组样本，投影 LEVEL/SPEED 字段，其他物品字段为零。验证等级不足、等于门槛、99 级、多次加成和 16 位回绕。该证据只覆盖速度，**不代表其他装备属性、唯一性或物品分配已实现**。

转换器导出可选 `speed`；新规则主将撤退决策间隔采用原 `46 + 2 × (敌速度 − 己速度)`，保持原式，随后沿源时钟递减。普通士兵及非撤退单位仍走各自原分支。没有速度的旧战中快照按原有零速度适配继续，加载时不补写速度。

本原包五个剧本的 401 条人物记录均配置黄鬃马，初始速度都是 1。因此初始对阵通常没有速度差；没有为了制造差异而改动人物或坐骑。

## 原脚本镜头

| 来源 | 已接行为 |
| --- | --- |
| SO `MoveCamera @0x1390` | 坐标乘 1000，带符号整数除法求每步增量，逐次写相机；精度达到十分之一单位时提前收敛；保留最后一次等待 |
| SO `LockCamera @0x1C0C` | 按方向、180 距离与累计 drift 跟随对象；每次等待后检查对象存活和上次相机与敌将的位置关系；结束时创建 30 更新的回镜头 |
| EXE `0x465700` | 每轮重新读取脚本数组长度；新追加的回镜头可以在同次源更新执行第一步 |
| host 256 → `0x43A638` | 直接写原坐标，不套普通管理器的 240–6560 / 0–800 钳制 |
| `0x43BA59`、`0x441E61` | 施法期间普通镜头让出控制；这不是冻结所有单位 |

`native_magic_camera_oracle.py` 执行原 x86 VM 和两段 SO。142 组原轨迹共 7288 次更新，覆盖双向追踪、目标移动、对象消失、负坐标、边界外写入、长短持续时间、同位置返回与微小整数步进。对象路径和相机宿主由构造快照提供；子协程创建作为边界记录。原调度器的动态追加顺序由静态代码核查，Web 集成另测同次执行。

新战斗保存 `cameraRules: native-script-v1`，以及脚本内的相机坐标、追踪/回镜头累计量和剩余等待。四个原 ShootObject 入口共用这条路径；没有镜头标记的旧快照保留旧行为。

起手前 40 次更新保留当前视图，原脚本首次定位后显示实际轨迹。施法中手动拖动、方向键、跟随切换和小地图不覆盖脚本相机；Web 视距选择仍可用于查看画面。镜头状态由模拟推进，渲染只读；缩放、暂停、窗口尺寸变化不抽随机数、不推进脚本。
