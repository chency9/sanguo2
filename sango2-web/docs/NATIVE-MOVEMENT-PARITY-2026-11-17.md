# 移动候选、目标占格与定点速度对照

新战斗已从连续向最近目标直线移动，改为调用原版候选格抽签与速度函数，并保存目标占格、前格、16.16 坐标、速度和剩余移动更新数。**这是移动函数与占格机制的接入，不代表原版整个单位调度器或整场战斗已一比一。**

后续：v2 战斗已接入递归友军让路；本页保留 v1 实现记录。当前行为和调度边界见[友军让路对照](NATIVE-YIELD-PARITY-2026-11-17.md)。

## 原程序证据

基准 EXE SHA256：`1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`。

| 地址 | 本轮核实的行为 |
|---|---|
| `0x43C2A5`、`0x48E560` | 八邻域候选按权重无放回排列；相对方向顺序是正前、左一、右一、左二、右二、左三、右三、正后。先抽完整候选列表，再查占格；最后一个非零权重也消费随机数 |
| `0x43C4C0` | 先按第一组权重找空格，失败后抽第二组。边界和撤退标志影响是否离场 |
| `0x43BF26` | 清除原占格、记录前格、写入目的格，然后人物开始移动；不能等走到以后再占格 |
| `0x43BE42` | 目标格中心为 `96*x+48,72*y+36`。非精确移动依次加 `below(48)-24` 和 `below(36)-18` 偏移；有符号 16.16 位移按横向 120、纵向 90 源像素限幅，除以 40 向零取整 |
| `0x43C084` | 无路时返回本格中心；判断是有符号 `vx>=256 || vy>=256`，不能改为绝对值。静止普通士兵前方已有敌人时保留朝向，否则朝向敌将；撤退兵和主将不走该转向分支 |
| `0x43BBE6` | 同行按方向扫描射程，遇活敌返回带符号距离；友军挡住后方敌人，死亡单位不挡，越界结束 |
| `0x43B961`、`0x4066AD` | 主将射程固定为 1，13 个兵种分别读取现役/预备射程表 |

`native-movement-profiles.json` 从 EXE 原地址读取前进、追击、撤退、严格和待命的 17 项参数；`native-movement-ranges.json` 从原表读取兵种射程。严格模式只有正前一个非零权重，待命模式全部为零。

## 可复现机器码对照

在 `web-port-research` 中运行：

```powershell
& .venv-ai/Scripts/python.exe tools/native_movement_oracle.py
```

脚本通过 Unicorn 执行上述原函数及原内部随机函数，使用原通用对象回调 `0x422847`；不替换移动/随机函数。本次路径不需要 OS API 替身。输入为构造的内存快照，非整场原版录像或 SAV 回放。

- 315 组候选排列：九个目标方向、多种权重、零权重、随机种子；核对八个候选及两个最终随机状态字。
- 280 组移动：四周阻塞、场边/角、精确/非精确、撤退与普通状态、原位回正；核对前格、占格、速度、朝向、离场标志及最终 RNG。
- 260 组同行查询：13 兵种、现役/预备、主将、正反方向、友军阻挡、死亡穿透及边界；核对原射程与带符号距离。

共 **855 组**原函数结果，同步到 `packages/core/fixtures/native-movement-vectors.json`。阻塞单位使用主将标志禁止递归推动，因此这 280 组不覆盖友军递归让路，也不覆盖原主将特殊退场分支。

## Web 运行与保存

- 新战斗标记 `movementRules: native-grid-v1`。无此标记的旧战中存档保留旧连续移动和已有随机调用顺序；进入新轮次使用新规则。
- 首次模拟时建立唯一占格。原 Web 布阵投影冲突时按稳定顺序分配最近空格，不消费 RNG、不改变部署画面。这是布阵兼容适配。
- 移动选定后立即预占目标格，随后逐次积分定点速度。每个 Web 步仍成组推进三次源更新，移动段保存剩余数；命令中途变化先完成当前段，不重新抽签。
- 移动抽签与 AI、命中、死亡共用现有原生双字 RNG。存读档恢复未完成的移动段，不重复抽方向或位置偏移。
- 死亡初始化从预约格和定点坐标读取源状态，显示间距修正不会改变第 6 行的脱离方向抽签。尸体保留显示偏移，脱离坐骑也保存相同偏移，避免死亡时跳回未修正的位置；这些偏移不参与模拟。
- AI 矩形查询与小地图读取同一目标格；已死亡、已逃离和已释放占格的退场单位不占用 AI 网格。不会让多个活单位预约同格。
- 渲染按移动朝向翻转人物，攻击开始时朝向目标；旧战斗维持旧渲染约定。Canvas 重绘不会改变移动或随机状态。
- Web 精灵显示尺寸仍大于原格子映射宽度，现有间距修正增加求解次数，保障百人和满编人物可辨。修正显示坐标不写回定点坐标或预约格；但当前攻击索敌仍读取显示坐标，因此这还不是完全独立的纯渲染层。
- 存档校验检查整数、速度、剩余更新数、合法朝向、有效格和重复活占格；拒绝携带移动状态却缺少版本标志的档案。

## 不能据此宣称一比一的部分

1. **单位调度尚未完整接入。** 原 `0x43B574` 普通/撤退/主将时钟、延迟消息、原全局对象链表顺序，仍由 Web 外层分组三更新调度代替。40 次运动积分是精确的；段尾剩余的 1–2 次源更新尚未立即用于下一次决策，撤退的原 46 计时也尚未接入。
2. **递归让路尚未接入。** 第二组候选在原版可同步更新未在本次更新过的友军，再检查其是否让开；运行层目前保守地把这些友军视为阻塞。原 `0x43B028` 的 7×7 影响网格尚未实现。
3. **命令/攻击仍有适配。** 原十种命令、五分队、阵形坐标、先后扫描概率、近战额外抽签、射程与攻击冷却还未完整连接。已核实的同行查询用于移动失败后的转向；普攻仍采用旧 Web 最近目标/距离判断。
4. **坐标与显示仍需实机校准。** 原逻辑横向 71 格、纵向 14 格映射到 Web 1200 宽战场；左右队伍采用 Web 玩家在左的约定。初始布阵、透视、显示间距和相机不是原屏幕逐像素复刻。
5. **退场时点为适配。** 原移动函数的退场标志立即释放占格，Web 在移动段结束后把人物标为逃离并处理主将败退。特殊主将/全队撤退消息链需另行对照。
6. 全部技能执行、AI 对 AI 战斗结算、战略完整状态及同一原 SAV 整局回放仍有差距；局部随机状态一致不等于整场 RNG 调用顺序一致。

## 验证

本轮累计 **6,459 项核心测试 / 18 文件通过**，含新增 855 组机器码对照和 9 项运行回归。覆盖满编唯一占格、先占格后移动、40 次定点积分、行走中改令、段中 JSON 存读档、退出边界、旧档兼容、损坏档拒绝，以及 200 对 200 交战中的显示间距、死亡源状态与显示偏移分离。

浏览器 **31 场景通过**，包含 1440×900、390×844 满编战斗、暂停不推进移动、撤退、战中保存/重载、六尺寸全屏、敌军进攻及 24 地形。TypeScript 检查与生产构建通过。截图：`screenshots/native-troops-combat-1440.png`、`screenshots/native-troops-combat-390.png`。

最后修正死亡源坐标后，全量核心、类型检查与构建再次通过；另复验桌面/手机满编、战中保存和重载结算四个浏览器场景，全部通过。开发服务 `http://127.0.0.1:25369/` 返回 HTTP 200。

Modern Web Guidance 检索了固定步长和 Canvas 动画计时；返回内容未涉及原版调度器语义，本轮未采用无关的 CSS 动画指导。浏览器回归按 Playwright Expert 的现有页面对象和自动等待方式补充。
