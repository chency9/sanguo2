# 原版 AI 决策内核移植与机器码对照

本轮替换了上一轮自行设计的战略策略、战场治疗/撤退阈值及“武力最高先出阵”规则。现在运行原 EXE 可定位的候选生成、权重、随机选择和冷却逻辑。**函数输入相同的对照已通过；整个战役和完整 AI 尚未达到原版一比一。** 本记录区分两者，不以测试数量替代全局行为验收。

## 原始基线与验证方法

用户提供的 1.05+ EXE SHA-256：`1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`。沿用 Rea / IDA 导出的汇编与伪代码，并直接读取这份 EXE 的机器码和常量。原文件未改动。

新增 `web-port-research/tools/native_ai_oracle.py`：用 Unicorn 2.1.4 在隔离的 x86 内存中装载原机器码，构造城市、道路、武将链表和随机状态后调用决策函数。不启动原 Windows 客户端，不调用系统 API。设置指令上限和运行超时；错误或未返回立即失败。

战略候选生成、顺序、选择与随机数不打桩。战术测试在兵种分类、网格计数、时钟查询边界提供观察值，执行原评分函数、技能读取与浮点运算；捕获权重后阻止实际命令执行。这证明评分函数在给定观察下相同，不证明 Web 网格、技能效果或移动与原引擎相同。

原 MSVC `_setdefaultprecision`（`0x46FE00`）请求 53 位精度。对照程序显式使用 x87 控制字 `0x027f`，避免 Unicorn 默认的 24 位精度导致边界权重偏差；这仍是明确的运行环境输入，尚非运行中客户端的控制字采样。

可复跑：

```powershell
cd E:\code\games\sanguo2\web-port-research
python -m venv .venv-ai
.\.venv-ai\Scripts\python.exe -m pip install -r tools/requirements-ai.txt
.\.venv-ai\Scripts\python.exe tools/native_ai_oracle.py
cd ..\sango2-web
pnpm exec vitest run packages/core/src/native-strategic-ai.test.ts
```

输出原始快照、机器码片段与函数哈希至 `web-port-research/evidence/ai/`；对照样本同时写入 `packages/core/fixtures/native-ai-vectors.json`，普通测试不依赖 Python、IDA 服务或执行 EXE。

后续军师内核、Rate/Level 加载差异和开战/入城配兵修正见 [军师决策补充](NATIVE-STRATEGIST-PARITY-2026-11-17.md)。下列测试数量是该补充之前的阶段记录。

原 `0x40D52F` 的候选类型 1 是空分支。本轮保留其候选及权重，并在抽中时不执行转账，没有擅自“修复”成新的玩法。

战役存档增加双字随机状态、各势力冷却、城市遍历顺序、可见城市记录、预备池及恢复计时；战中保存评分调度、命令标记和随机状态。旧存档保留已有资源和战斗数据，并显式初始化缺失的 AI 状态。最近 32 次战略选择记录在 `session.nativeAI.trace`，用于排查无行动、选城或联合分支问题。

## 联合出兵的原版未定义栈输入

`0x40C635` 在 `0x40C965` 比较 `[ebp-0x28]` 和 `[ebp-0x30]`，在该路径进入前没有初始化。伪代码和汇编一致，不能把它们误读成两城现有兵力。

对照样本记录原机此次实际比较结果，再把该输入交给 TypeScript，8 次命中分支均对齐。Web 运行中没有原进程旧栈，采用显式 false 分支兜底，并在 trace 的 `unresolvedCooperationReads` 中计数。因此该分支**没有获得无条件的一比一证明**。验收需采集原客户端完整调用现场，或确认用户接受稳定化原版缺陷；本轮未自行把稳定化解释为原版等价。

## 必须继续闭合的全局差距

1. **输入状态与顺序**：Web 初始每将 80 兵、合并现役/预备兵、城池占领后的将领分配仍与原版不同。Web 有主无将城市也不等于原链表结构，适配器跳过此类决策源以避免原函数除零。原兵力初始化、完整将领/城市链表顺序和原存档导入仍需接入。
2. **时间与随机数调用链**：修正版日历机器码是每月 300 回调、每天 10 回调；Web 据此推进 AI，但行军仍按每天道路单位结算。后续已将普攻命中/伤害与 AI 接入同一原版 RNG，见[普攻对照](NATIVE-COMBAT-PARITY-2026-11-17.md)。移动、事件顺序及未实现行为仍改变整局的随机数消费序列；完整时间与全局随机流必须联动校准。
3. **战场观察与动作**：Web 连续坐标投影为 55×14 网格，只是适配；敌军推进分区、布阵可达性、军师状态、技能打断和精确前后军命令仍需原网格与命令系统。已记录原选技结果，但未实现的技能不扣蓝、不虚构效果；不能把“选对技能”当作“执行完整技能”。
4. **出征执行链与自动战斗**：双军队、资金、将领排序和实时战斗城防战力加成已接，但原军团属性、行军中改道/撤军、电脑之间战斗与俘虏结算仍有 Web 规则。函数级选择通过不能证明随后的局面一致。
5. **内政与人才**：原 `0x402711` 的搜索/内政、追赶经验、装备分配尚未恢复完整状态和效果；军师选择与部分效果已接入。后续已恢复忠诚/疲劳/士气的驻城与实时战斗链，见[人物状态对照](NATIVE-CONDITION-PARITY-2026-11-17.md)，但原年度阶段、人物登用、投降/叛逃等输入输出仍不完整。原策略替换后不再运行之前每五天免费式候选内政循环。
6. **运行实证**：尚无原客户端与 Web 从同一存档、同一 RNG、同一操作开始的连续回放。最终验收须比较每次决策的输入、候选、随机消费、选择、执行结果及下一次状态，出现第一处分歧即定位；目前不能宣布整体一比一。

## 本轮验证

- 320 组原机器码战略候选/随机对照，覆盖所有实际候选类型 1/3/4/5/7/8/9、五套性格参数。
- 400 组战术七权重、240 组选技九权重、80 组出阵选将、80 组阵形权重/选择对照；4 组随机种子各 100 次原机器码输出。
- 本轮核心与资源测试共 1196 项通过，其中原机对照模块 1128 项。五剧本各 60 日逐日检查保存恢复与状态合法性，玩家战斗快速结束，此项不是长期平衡测试。
- Chromium 25 项覆盖来袭、攻守战、战中存读档、结算、地图及六种视口。经济测试已纳入原版自动预备池开支；单场保存/占城案例延后无关势力决策，专门 AI 案例保持正常调度。
- TypeScript 类型检查、生产构建及 4 项 Python 资源属性测试通过；固定端口 25369 返回 HTTP 200。
- Modern Web Guidance 检索了确定性随机数与 JavaScript 整数计算，未找到适用指南，未套用无关网页模式。Playwright Expert 用于现有 POM、角色定位、受控内容响应与独立测试场景。
