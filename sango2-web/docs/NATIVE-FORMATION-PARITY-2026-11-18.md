# 九种普通阵形部署对照（2026-11-18）

新战斗已用原版九种普通阵形的坐标表初始化逻辑占格、固定点位置和双方镜像；阵形选择受当前武将学习表限制。**234 组部署函数样本全部一致，不代表整场战斗或界面已达到一比一。** 士兵画面位置仍使用 Web 可读性布局，与逻辑占格分开保存。

后续已接入独立五分队、十种士兵命令执行分支和 AI 分批推进，见[五分队与军令对照](NATIVE-COMMAND-PARITY-2026-11-18.md)。下文保留阵形这一轮的验证边界；原版菜单和显示坐标仍需继续校准。

## 原程序证据

基准为用户提供的 1.05+ EXE，SHA256：`1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`。

| 地址 | 核实内容 |
|---|---|
| `0x485B10` | 每阵形五个分队的坐标表指针 |
| `0x485DA8` | 每阵形五个分队人数权重及基准横坐标 |
| `0x404780` / `0x404DAF` | 基准横坐标与分队位置查表 |
| `0x48E4D0` | 主将纵坐标 6 |
| `0x442CB6` | 按总兵力偏移、部署模式变换、左右镜像 |
| `0x442D38` | 分队兵员创建、占格冲突后的横向搜索 |
| `0x442EFA` / `0x443498` | 左右部署入口 |

工具位于相邻研究项目的 `tools/native_formation_oracle.py`。在该目录执行：

```powershell
.\.venv-ai\Scripts\python.exe tools/native_formation_oracle.py
```

提取九阵共 1,800 个坐标点。部署对照包含九阵 × 九种现役/预备人数 × 两个朝向的 162 组普通部署，以及九阵 × 四种坐标变换模式 × 两个朝向的 72 组阻塞部署；后者显式阻挡两个位置，验证空格搜索。共 234 组，包含 28,242 名士兵的输出。

隔离执行仅替换渲染资源分配边界 `0x4217FE`；被测坐标查询、人数分配、变换、占格与冲突搜索执行原机器码。它不是完整客户端启动或全局战斗回放。其他模式的向量用于验证变换函数，尚未表示对应军师阵流程已接入游戏。

原始输出为研究目录下 `evidence/ai/native-formation-positions.json` 与 `native-formation-vectors.json`；运行时表和测试副本分别为 `packages/core/src/native-formation-positions.json`、`packages/core/fixtures/native-formation-vectors.json`。

## 接入行为

- 普通阵形槽位 0–8 对应方、圆、锥形、雁形、玄襄、鱼丽、钩形、冲锋、箭矢。兼容原资料的简繁标签。界面仅列当前武将已学阵形；切换出阵武将后重新计算可用项和默认项，核心也拒绝未学习的阵形。
- 缺失、空或未知学习资料只回退方阵，不视为全阵形解锁。敌方阵形决策仍遵循已核实的七槽选择函数，不自行补造冲锋、箭矢的 AI 权重。
- 分队顺序为 1、3、4、5、2，各队先预备后现役，共用队内位置索引。主将和士兵占格先后参与冲突判断；部署第二方时计入第一方占格。
- 普通模式横向偏移为 `trunc((200 - 总兵数) / 25)`，镜像为 `71 - x`；其他模式按原函数分支处理。原始格中心固定点为 `(96*x+48)*65536`、`(72*y+36)*65536`。
- 新战斗保存 `deploymentRules: 'native-tables-v1'`，首次准备移动状态时接入真实阵形格。AI、碰撞和移动继续读取同一逻辑占格；初始化不额外消耗随机数。
- 无部署标记的旧战中存档继续原有像素投影及已存移动状态，不强制重排；旧阵形别名继续兼容。旧档当前值若不在学习列表中，以禁用的“存档阵形”项显示，可改选已学项。
- 重新布阵保留已下达军令。修复敌方方阵显示受玩家阵形影响，以及逻辑/显示原点分离后个别单位显示越界、继而无法通过存档校验的问题；显示约束不改逻辑固定点、占格或随机状态。
- 学习提示通过 `aria-describedby` 关联阵形下拉框。窄屏允许控件与提示换行，保持全屏战场控制可用。
