# 友军递归让路：原函数对照与接入

本轮接入原版第二组候选格中的友军提前更新机制。新战斗使用 `movementRules: native-grid-v2`；v1 战中存档继续原有“不尝试让路”的更新顺序，没有标记的更早存档继续连续移动。

后续：v3 已将单位内部细化到逐次源更新，接入原决策计时和攻击搜索。本页保留 v2 的历史验证记录，当前实现范围见[单位时钟对照](NATIVE-UNIT-CLOCK-PARITY-2026-11-17.md)。

## 核实的原规则

原 `0x43C4C0` 先完整抽取第一组候选并尝试空格。第一组失败后，完整抽第二组，再逐个尝试；尝试期间给当前移动者添加 `0x1000` 递归标志。

`0x43C20D` 对目标格的处理顺序为：

1. 格子空，返回成功。
2. 占用者本次已经更新，拒绝。
3. 占用者阵营不同，拒绝。
4. 占用者有 `0x1001` 中任一标志（主将或当前递归链），拒绝。
5. 调用占用者原事件回调，消息为 `2,0`（正常单位更新）。
6. **重新查询目标格是否为空**；发生过回调不代表让路成功。

原 `0x43DDBF`/`0x43BDBB` 拒绝同更新重复处理。原 `0x43BE32` 在移动、阻塞和普通运动更新路径记录已更新时刻。让路可沿多个友军继续递归；回溯时由内向外预约腾出的格子。

另核查了 `0x43B574`：普通决策重置 40，撤退重置 46，主将撤退还使用双方速度差；`0x43BCA7` 的攻击搜索冷却仅在决策时递减，普通单位抽取搜索方向，撤退单位只查朝向。本轮没有把这些时钟改写进 Web 外层，也没有宣称攻击调度完成。

运行 `web-port-research/.venv-ai/Scripts/python.exe web-port-research/tools/native_yield_oracle.py`，生成研究 evidence 和核心 fixture 的 `native-yield-vectors.json`：

- **96 组资格检查**：空/占格、敌我、普通/预备/主将/递归/撤退/死亡标志、过去/本次/未来更新戳。执行原 `0x43C20D`，只观察原通用对象回调入口，不改写执行结果，核对消息与返回值。
- **72 组真实回调链**：2、3、6、10 人，每种分别以可移动、主将、递归中、已更新、敌军、时钟未到的尾部结束，使用多个种子。实际执行 `0x43C4C0 → 0x43C20D → 0x43DDBF → 0x43D125` 及更深调用；核对回调顺序、所有单位位置/速度/更新戳、最终双字 RNG。

链式夹具使用构造的动作资源与严格向前命令，攻击搜索冷却为 100 以隔离让路分支。没有替换移动、回调、随机函数，无 OS API 替身；但这是受控内存快照，不是原客户端完整战场回放，未覆盖整套攻击和消息时钟。

## 运行实现

- `native-unit-yield.ts` 保留资格检查顺序和回调后再次查询。
- `battle.ts` 将每个单位原有的正常更新收敛到同一入口，让路调用和外层轮询都走该入口。活跃递归集合防止回环；保存的 `updatedAt` 防止同一更新重复步进、重复推进攻击动画或再抽方向。
- `battle-movement.ts` 每次嵌套更新后重建占格查询，防止深层友军移动后读取旧映射；原地转向检查推迟到真正的回退时执行，避免使用让路前的旧前方目标。
- 移动状态和 RNG 持续随存档保存。验证器拒绝未来/非整数更新戳，也拒绝 v1 快照混入 v2 更新时间。
- 近邻桶替代 v2 显示间距修正的全员两两比较，保持 i/j 顺序；校正跨桶时重新查询，不遗漏新近邻。收敛后提前结束，满编最多 18 轮。v1 仍使用原 12 轮，更旧版本仍使用 3 轮，避免改变其既有位置/RNG 后续输入。
- 展示间距仍是 Web 适配，不是原版物理。近邻算法有独立暴力对照测试，验证跨桶移动下处理顺序和最终位置一致。

## 验证与边界

新增运行测试构造被友军围住的单位，证实 v1 停留、v2 提前更新前方友军后进入空格，且被提前更新者本次只推进一次。另覆盖 v1 存读档顺序、未来更新戳拒绝，复用满编唯一预约格、百人/满编间距、段中保存重放和死亡随机调用回归。

**仍未一比一的核心差距：** 外层更新还是三次源更新成组；本轮的“本次已更新”对应 Web 组时刻，不能等同于原版逐源更新与全局链表。攻击搜索、普通/撤退/主将决策时钟、十种命令、五分队、7×7 影响网格以及技能完整执行仍待接齐。已验证的是让路资格、递归回调/回溯与局部 RNG 规则，不能据此推导整场行动顺序一致。

核心 **6,630 项 / 20 文件通过**。浏览器回归 **31 场景通过**，覆盖桌面和手机满编战斗、暂停、撤退、轮战、敌军进攻和战中保存/重载。类型检查与生产构建通过，25369 开发服务返回 HTTP 200。全量核心曾在与浏览器并发争用 CPU 时触发满编重放测试默认 5 秒超时；浏览器结束后单独运行全量通过。满编间距压力测试显式使用 15 秒上限，未减少模拟步数或降低间距要求。

本轮使用 Modern Web Guidance 检索固定步长/Canvas 调度；检索结果讨论浏览器任务调度等，未直接适用于原程序单位事件顺序，没有引入异步让路或浏览器优先级 API。浏览器回归沿用 Playwright Expert 的页面对象与自动等待方式。
