本页记录年度内政基础实现。后续已补搜索、登用成长、库存和自治，现状以[搜索与自治对照记录](NATIVE-POLICY-SEARCH-PARITY-2026-11-19.md)和[完整差距表](PARITY-STATUS-2026-11-19.md)为准。以下验证数量是基础阶段的历史运行记录。

## 现在可以操作什么

新局进入「内政经营」，选择己方城池和执行武将，可批量开发、任命太守、从城内预备池补充部队、查看开发记录。内政阶段不推进行军和战略AI；「内政終了」后返回征战。重新打开经营界面可查看报告和配兵，但不能重置本年的开发机会。年度转换重新进入内政，恢复每将行动机会。

开发记录、行动标记、当前太守、年份和阶段均写入 Web 存档。旧存档不会被静默改成新经济规则，可在经营界面明确启用年度内政；启用保留金钱、人口、城防、兵员、日期和随机状态。旧局的每日按钮逻辑仅作为历史存档执行路径保留，新规则不能调用它来额外开发或买兵。

| 内容 | 原函数 | 当前行为 |

| 城防开发 | `0x427947` | 城防未满999时，基础收益为 `trunc(4×执行将武力/10)+RandomBelow(12)`，套用相同太守智力修正，封顶999 |
| 调用顺序与花费 | `0x427B9E` | 先人口、后城防；关隘或已达上限的对应分支不抽随机数；这些开发函数没有300金费用 |
| 行动限制 | `0x4273C0/0x427701/0x423765` | 原人物+149的bit1表示本轮已行动，年度清除；Web按人物保存，不再按城市每日限制；封顶无收益仍耗本将行动 |
| 年度收入 | `0x423824` | 非关隘收入 `trunc(75×人口/10000)+2250`，包括没有势力的普通城市；新规则不再每月按人口千分之一发钱 |
| 城内预备与配兵 | `0x41AFAB/0x41AF58/0x401910` | 已有原自动征募池继续工作，每补充预备兵花100金；手动分配转移已有兵，不再支付200金、不减少人口；填现役后填将领预备，受等级上限约束 |
| 太守 | 城市+20、开发和出兵调用链 | 现任太守作为运行状态保存，参与开发修正与AI出征队首选择；不得任命外城或行军武将 |

## 机器码与游戏内验证

`web-port-research/tools/native_policy_oracle.py` 在隔离的 Unicorn x86 内存中，使用同一已固定SHA-256的原EXE，直接调用原开发人口、开发城防、年度收入三个函数；不启动Windows客户端、不替换RNG。240组输入覆盖关隘、人口满值/差1封顶、城防998/999/1000、不同武力/智力/太守能力。TypeScript逐项比较收益、最终数值、原报告值和两字随机状态。

样本：[native-policy.json](../packages/core/fixtures/native-policy.json)。实现：[native-policy.ts](../packages/core/src/native-policy.ts)。集成与原码对照测试：[native-policy.test.ts](../packages/core/src/native-policy.test.ts)。浏览器流程：[policy.spec.ts](../tests/policy.spec.ts)。

本轮核心40个文件、12,594项测试通过；完整Chromium浏览器49项、Python5项、类型检查和生产构建通过。年度内政专项浏览器3项覆盖1440宽与390宽、原生对话框焦点/Esc、开发/任命/报告/配兵和存档；核心集成另覆盖批量命令原子性、已行动者恢复、统兵上限、预备池守恒、跨年暂停和不重复税收。结果保留在[命令日志](evidence/commands/)；全游戏状态不以测试数量计算还原比例。

## 基础阶段记录的边界及后续变化

1. **搜索与归附成长已在后续接入，原对白仍缺。** 城市类别、邻城/在野名单、忠义分支、经验和逐级成长已有780组相关原码样本，具体边界见后续记录。
2. **四种自治已接，AI年度经营仍缺。** `0x427701`含四种开发/搜索权重，现可保存和施行；`0x402711`依次搜索/开发、两段追赶经验、库存使用/换装的完整链仍须恢复。
3. **年度事件先后仍不完整。** 原入口 `0x4238AF/0x423885`先年度在野出场，再清行动标记、AI年度处理和有条件税收。当前只接行动阶段与税收；成年/历史/System.SO、原特殊开关和整局调度缺口保留。Web以360日映射年度，初始内政及跨年呈现还需实际原客户端录像对齐。
4. **人物、城市链表顺序仍用Web状态适配。** 后续已确认初始城市人物头插、全局人物尾插，批量开发/搜索及自治据此执行；跨行军和占城的完整变更历史仍有Web适配。原太守离任后自动接任的优先级尚未证实，当前保留合法驻城人选并使用明确兜底。
5. **新局已使用原等级兵槽初始化，旧存档保留现有兵。** 城内预备池初始0已核实；完整入城/出征重配仍须恢复，不能据此声称所有兵员流程一比一。
