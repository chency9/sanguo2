## 驻城计时细节

- 疲劳大于 0 时，独立计时器递减至 `<=0` 才减一点；周期 `45+trunc((999-城防)*45/2997)`，保留原 int32 乘法和 int16 存储行为。
- 疲劳低于 60 且士气低于 70 时，每 360 回调恢复一点士气；疲劳至少 60 时每 100 回调降低一点士气。两条路径使用两个独立计时器，切换条件不会清零对方计时器。
- 士气至少 40、忠诚低于 90 时恢复忠诚；增加后的忠诚小于 30/50/70/其余，对应下次计时为 300/450/900/1800。士气低于 40 时每 150 回调降低一点忠诚。
- 例如疲劳 60、士气 39、忠诚 29，三个相关计时器都是零：同一次回调依次变为 59、40、30，随后忠诚恢复计时设置为 450。

战役沿现有每天十次原回调调度；行军人物暂停上述驻城恢复。HP/MP 仍由原来的独立路径处理，本次对照只证明状态和五个计时器，不声称原函数末尾 HP/MP 最低 1、兵力容量截断已完整接入。

## 存档、界面与兼容

`GeneralState` 和 `BattleCommander` 保存 `morale/fatigue/loyalty`，`nativeAI.recovery` 保存五个独立时钟。战阵结算只执行一次；连续选将时携带已更新疲劳和忠诚；全场结束后回写原武将。新战役基础值为 80/0/90，演武从当前人物状态读取且不写回战役。

旧战略存档缺字段时，读取保持原有状态，驻城回调或入场时采用明确的 80/0/90 兜底。已有字段不覆盖。旧战中存档缺少士气时，正在进行的普攻保留原先中性 50 输入；下一阵重建时使用新的状态初始化。旧战斗未记录计策效果不会重新补施。旧资料可能已有错误的 `loyalty` 数值，当前保存兼容保留已有值，未提供原 SAV 迁移或完整历史恢复。

名册新增“士气 / 疲劳 / 忠诚”列；横向滚动时姓名和表头固定，滚动区域可键盘聚焦，采用原生 table/caption/th scope，不用颜色单独表达状态。已检查 1280 和 390 视口截图，以及 JSON 导出/导入后的显示。
