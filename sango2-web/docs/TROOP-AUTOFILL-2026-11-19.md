# 点击补满、逐兵更新与窗口收尾

配兵窗口现在保留原版的进行中状态：**点击“补满部队”后持续补兵，每次更新一兵，先现役、后预备；松开鼠标不会停止。** 切换武将先补完旧武将，关闭窗口前也先完成配兵。兵员只来自当前城市预备池，不扣金钱、不消耗年度行动、不调用随机数。

此前文档将此行为称为“按住补兵”，这是根据标记名称作出的错误推断。本次执行原按钮和鼠标分发代码后予以纠正。

## 原程序依据

固定EXE SHA-256：`1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`。

| 原地址/事件 | 实际行为 | Web对应 |
| --- | --- | --- |
| `0x41A7CE`，事件4 | 将 `0x4A6424` 设为1；本事件不移动兵员 | 点击或键盘激活后启动任务 |
| 同函数，事件8 | 标记为1时移一兵；城市池空或两槽已满时清标记 | `nativeAutofillTroops()` 与逐兵命令 |
| `0x41D160`，事件512 | 检查输入标记和严格命中区域，再转发事件4；释放/移出不清补兵标记 | 点击启动，释放后继续 |
| `0x41C24E` | 对当前活动窗口的各子控件分发事件8；不检查鼠标是否按下 | 一个逻辑更新执行一次补兵 |
| `0x41A6FB` | 标记等于1时，先现役后预备补到边界，并清零；其他标记不动 | 任务收尾 |
| `0x4169E2` → `0x416D19` / `0x416D27` | 先调用收尾函数，再写选中武将指针 | 切将前完成旧将配兵 |
| `0x416EAB`，接受的关闭事件 | 收尾后进入通用关闭路径；子窗口状态可阻止普通关闭 | 关闭Web内政对话框前收尾 |
| `0x41A923` | 打开兵种面板的操作内调用收尾 | Web直接选择兵种前收尾；独立子窗口未恢复 |

最后一兵补完时，原标记仍为1，**到下一次更新发现空池或满槽时才清零**。重复点击仅重新置1，不创建第二个并发任务。逐兵增减和原滑条回调不清此标记；Web调兵过程中仍可调整人数，后续补兵继续处理新的兵槽状态。

## 浏览器适配与剩余差距

- Web用`requestAnimationFrame`调度，最多每秒60次逻辑更新，每次最多一兵；不为落后的帧批量补算。**原版的实际更新频率尚未证实**，不声称两端耗时一致。
- 原版已证实切将、关闭、打开兵种面板的收尾顺序。Web另提供直接换城和切栏目，隐藏标签页、页面离开、组件卸载及存档前关闭对话框也收尾，避免异步任务遗漏或串将。这些是浏览器生命周期适配。
- “立即完成补兵”是Web补充操作。系统开启减少动态效果时直接得到最终分配结果，过程中切换该偏好也完成收尾；不依赖动画结束事件提交兵员。
- 兵种在Web面板中直接可选；本次只把配兵收尾接到选择操作前，未恢复原子窗口的动画、阻止关闭状态、原字号、声音与逐像素布局。
- 原客户端的真实输入、计时和连续存档回放仍待验。完整一比一的其他漏项继续保留在[总账](FULL-PARITY-BACKLOG.md)，不以本次局部差分代替整局验收。
