# ArrowSupport：原脚本、箭矢对象与战场接入

本次把六项箭雨技能从通用范围伤害改为原 `ArrowSupport` 流程。弓兵动作产生升空箭，下落箭逐格查找目标；命中回调决定伤害与燃烧对象。这里记录的证据支持局部脚本与对象规则，尚不等同于整场战斗一比一。

| 技能 sequence | 原脚本 ID | 入口 | 数量参数 | 火箭参数 |
|---|---:|---|---:|---:|
| 4 | 503 | Magic3 | 17 | 1 |
| 15 | 515 | Magic15 | 29 | 1 |
| 30 | 534 | Magic34 | 66 | 1 |
| 45 | 545 | Magic45 | 8 | 0 |
| 72 | 572 | Magic72 | 33 | 0 |
| 87 | 590 | Magic90 | 56 | 0 |

六个入口均调用 `SCRIPT_MAGIC.SO 0xB22C`。Web 使用限定的 28 个原脚本符号和 1,454 条整数指令，保留原分支、调用栈、等待、共享变量和随机数消耗。执行状态只含 JSON 数据，浏览器帧率不参与施法计算。

## 已恢复的行为

- 第 20 次更新锁定施法者并切换镜头，第 40 次更新解除锁定，第 70 次更新创建场外弓兵。
- 原版 `0x43A7AC` 从存活士兵名单随机抽取目标；保留兵槽顺序。士兵不足时，原脚本通过 `host784` 创建补充落箭，不用推测的命中概率。
- 原版解析器与动画步进器确认：弓兵对象 16001 / 16002 的第 55 帧触发脚本 6003 / 6004，第 126 帧移除；升空箭与落箭对象在原节点执行移除。
- 下落箭在高度低于 96 时经过原阵营标记与格子占用检查。带 `OF_BOMB` 的箭落地后先进入死亡动作，不继续命中。
- 士兵先接收原通用碰撞事件 65539，再执行 `ArrowCallback1 / 2`。敌将受到 `ATTACK / static8` 的整数伤害；产生正伤害后，除数乘二。
- 火箭回调附着原 10015 燃烧对象；原 768 / 769 音效、延迟、镜头和调色状态均经过宿主事件接入。
- 战中 JSON 存档保存所有协程栈、对象位置、动画时间、共享除数、镜头和随机数；轮战结束会清理进行中的施法。

`tests/battle-arrow-support.spec.ts` 的两个浏览器实战用例已通过，分别使用 1440px 的火箭天襲与 390px 的飛矢。测试监测原图集的实际 `drawImage` 调用，检查弓兵、升空箭、下落箭及燃烧图层，同时核查真实士兵伤亡、镜头归属、暗场和保存后刷新读取。左右落箭共享 SHP 图块，绘制监测明确记录图块别名，运行中的对象记录另行确认对象身份。

浏览器夹具先正常创建原初始化新局，经实际界面导出存档，只删除该存档的 `movementRules` 和 `captureRules` 再导入，使用保留的旧战略行军入口快速抵达测试战斗；原武将装备、兵槽及 `native-grid-v3` 战场均保留。这两项用例验证箭雨与战中存档，不验证战略行军速度。生产行军逻辑没有为测试改速。截图位于仓库根目录 `docs/images/arrow-support-30.png` 与 `docs/images/arrow-support-45.png`。

## 证据边界

原 x86 VM 执行字节码、整数分支、等待和随机数。对象分配、世界查询、音画播放与镜头仍通过明确的宿主边界接入；部分对象更新由已取证公式和原解析器输出驱动。独立宿主样本证明了随机取兵、节点时间和碰撞门槛，但未运行原客户端完整混合对象列表。

目前尚未完成同初始存档、同输入的整场原客户端连续回放，也未完成 DirectDraw 调色、叠加混色与逐像素图像对照。通过这些测试不能声称整场战斗或六技能的全部音画已经百分之百一致。
