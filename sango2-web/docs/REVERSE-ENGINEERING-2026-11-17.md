使用用户指定的 Rea 6.8.0 本地 CLI 与已安装 IDA Professional 9.4。原游戏 EXE 未修改，对分析副本进行静态分析，未运行旧客户端来采样战斗。

原件与副本 SHA-256 相同：`1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`。
桥接服务位于本机 `127.0.0.1:13337`。Rea 字符串查询与技能加载器反编译原始 Evidence 均已保留。旧桥接插件导入 PyQt5 时曾出现兼容提示；另用独立数据库批处理直接调用 IDA/Hex-Rays 导出，避免依赖 GUI 打开伪代码。没有修改安装目录、原文件或桥接插件。

## 已定位的原生规则

| 项目 | EXE 地址 / 来源 | 静态结果 |
|---|---|---|
| 技能数据布局 | 0x42F3C8、0x40A322 | 每项22字节；MP +8、POWER +10、ATTACK +12、SCRIPT +18；不能以技能序号替代脚本编号 |
| 人物属性 | 0x42D1A3 | STR 写 +52，INT 写 +54 |
| 初始集气 | 0x442EFA、0x443498 | 两侧战斗结构基础值60000（后续军师效果需另行处理） |
| 普通集气增量 | 0x43E72E | max(STR,INT)，有效军师标志0x20可取倍率50/66/76/130/150/200%，使用整数除法 |
| 更新与上限 | 0x43E964 | 非死亡状态更新后封顶120000；0x4000状态则扣50（该分支没有零截断） |
| 施法条件 | 0x43B887、0x43BA23 | 满集气且无对应阻断标志；技能ID不为0、MP足够。不是完整学习/选技验证 |
| 施法成本 | 0x43BAE3 | MP减配置MP，集气减120000×POWER/100，存在额外成本倍率；两者减后至少0；ATTACK写脚本全局槽4 |
| 脚本施法侧 | 0x43BA59 | 全局槽5写当前施法侧标记 |
| HUD集气 | 0x441212 | 剑形WAR09/0B为集气填充，WAR0A/0C为底图；有效进度132像素，柄区29像素；原画面HUD从y344开始 |
| HUD体力/技力 | 0x440F59 | 单独使用WAR01–07，容量条长 min(107, trunc(107×max/150))，填充再乘current/max；不是统一100%长条 |
| 命疗术 | Magic1→Heal→CreateHolyLight→IncreaseHP | 从初始HP开始逐点写入initialHP+i，每次写后wait(2)，循环至ATTACK=30；host280截断至最大HP，满血仍走完循环 |

VM有90项opcode入口，宿主表基址0x4A69B0；host279/280分别位于0x4A6E0C/0x4A6E10，对应读取/写入HP。该关系由汇编索引和地址算术证实。落月弓的Magic2调用ShootObject，资源来自magic/003；命疗术用magic/016，不能按技能ID找同号目录。

## 最终 Web 变化

1. 新战斗以半槽集气开始，正常交锋增长至120000；存档保留集气，旧存档缺字段仍可加载。轮换出阵按基础初值开始。
2. 修正剑槽误显示HP的问题，恢复原图剑槽、独立体力条和技力条。双方反向填充，容量长度按原生算法；新战役记录maxMp，避免消耗技力时把当前值当最大值。
3. 独立原生规则模块接入倍率和技能成本算法、来源地址及测试。仅当武将原始技能字段包含已确认的技能序列时显示技能入口；命疗术按脚本逐点写入并等待，落月弓仍拒绝执行，直到投射物命中链完成。
4. 集气用原生progress暴露名称与数值，体力/技力用meter语义，装饰图片不重复朗读。窄屏维持自适应布局，非原版640×480像素对照。

## 未解决的差距

- Web每秒20步、每步3个源更新仍沿用先前的暂定时钟；EXE更新的实际频率、速度档、暂停/施法调度还未运行测量。因此集气**每次更新的公式**有证据，实际充满耗时尚未校准。
- 当前Web撤退停止集气，未接原生0x4000状态扣50；军师标志、初始加成及异常状态尚未接入。
- 命疗术的逐点数值和调度等待已接入核心；暗场、相机、光效、暂停其他单位仍未复刻。落月弓的投射物命中伤害仍未开放，不能只取ATTACK=15即认作最终扣血。
- HUD剑槽满气暂用静态提亮；原版随内部计数闪光的节奏未复刻。字库、等级、计时、命令面板仍未完整对齐。
- 普攻、兵种、阵形、战略AI、成长等此前列出的差距仍然存在。
