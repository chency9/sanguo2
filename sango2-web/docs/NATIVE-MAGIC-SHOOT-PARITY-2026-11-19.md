# ShootObject 武将技：原码对照与实战接入

日期：2026-11-19。适用版本：《三国群英传2 修正版 1.05+》。

## 本轮结果

新创建的战斗通过 `magicRules: native-shoot-v1` 接入四个原始脚本包装器。没有这个标志的存档继续使用原有执行器；加载不会更改弹道、等待次数或随机调用顺序。

| 技能 sequence | 技能 | SCRIPT | 原 SO 包装器 | ShootObject 参数 | 飞行对象 |
|---|---|---|---|---|---|
| 2 | 落月弓 | 502 | Magic2 | style=0, flaming=1 | 13001 |
| 13 | 御飛刀 | 514 | Magic14 | style=1, flaming=0 | 13003 |
| 52 | 落日弓 | 552 | Magic52 | style=0, flaming=0 | 13001 |
| 59 | 鬼戟 | 558 | Magic58 | style=2, flaming=0 | 13005 |

技能 sequence、SCRIPT 编号、Magic 后缀和素材目录互不等同。鬼戟此前走暂定范围扣血分支，现在按 Magic58 的飞行对象处理。

## 可重跑的原程序证据

EXE SHA-256：`1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`。

新增工具位于仓库根目录 `web-port-research/tools/`：

- `native_magic_shoot_oracle.py`：在 Unicorn 中执行 EXE 的整数 VM 和原始 `SCRIPT_MAGIC.SO`。120 个快照涵盖四个包装器、两个方向、五处出生位置及三组 RNG；记录每个主脚本宿主调用的参数、时刻、结束时间和最终 RNG。
- `native_magic_impact_oracle.py`：执行原始对象运动/碰撞、淡出、伤害和集气函数。24 个碰撞快照、48 个伤害/集气快照、12 个 SO 回调入口和三种淡出轨迹。

生成的快照位于 `packages/core/fixtures/native-magic-*-vectors.json`。单元测试无需 EXE；重新生成原码证据需要在本地准备原始分析文件与 Python 依赖。

明确边界：主脚本 oracle 用合成句柄观察图形、音频和世界宿主；字符串分配替换为不可变字面量标记。整数控制流、等待回调及宿主 771 的 RNG 原码不作替换。子视觉协程只记录启动参数，未在主脚本 oracle 中执行。碰撞 oracle 在目标动作/死亡转换和脚本创建处观察事件。该证据证明这些边界内的函数行为，不代表完整原版客户端或整局战斗的执行顺序。

## 主执行链

原始脚本位置均为 SO 文件偏移：

- `ShootObject @ 0x6998`，四个技能共用主流程。
- `ShootObjectCallback @ 0x5CA4`，注册脚本编号 3001。
- `Hurt @ 0x12B8`，进入直接伤害宿主。
- `FlyLight @ 0x6584`，飞行光效子协程。
- `HitGeneral @ 0x3B34`，主将命中粒子子协程。

原 VM `wait(N)` 在进入等待时就执行第一次计数递减，在 N 个源更新后恢复。主脚本对照得到：

| 源更新（从 0 开始） | 行为 |
|---|---|
| 0 | 加载素材、进入施法流程 |
| 5、10 … 40 | 亮度由 16 逐步降至 8 |
| 40 | 设置暗调色板，读取 RNG 镜头抖动，锁定施法者受伤状态并定位镜头 |
| 55 | 设置起手动作，解除受伤锁定 |
| 70 | 播放对应音效、创建飞行对象、安装碰撞脚本并启动视觉/镜头子协程 |
| 飞行阶段 | 每源更新检查对象存活和世界 X 边界，等待 1 次计数 |
| 对象消失后 60 | 开始恢复亮度 |
| 再经过 40 | 完成亮度恢复并结束主脚本 |

世界范围为 0–6816；对象出生时已在边界之外，会在同一次脚本执行中移除。不能把这条路径统一压缩成 24 帧飞行。

## 坐标、碰撞和命中

1. 相机起手位置由第 40 个源更新时的施法者位置计算。飞行对象在第 70 个源更新读取施法者当时的完整 16.16 固定点位置；不锁死在点击施法时的位置。
2. 飞行朝向由原脚本 global 5 决定。Web 左、右部队分别适配为向右和向左飞行；这是坐标/阵营适配，不是原内存阵营指针的声明。
3. 飞行速度为每源更新 16 个世界单位；一般对象前移 80、高度 80，鬼戟前移 36、高度 69。坐标宿主保留小数部分。
4. 对象通用运动先执行，再查询当前 96×72 世界格。碰撞只读取源占格，不读取为画面可读性而分离的 `unit.x/y`。
5. `0x40A878` 将目标分类为敌将、敌兵、友将、友兵；`0x40A8CC` 按对象碰撞掩码和高度 `<96` 检查。落月弓、御飞刀、落日弓只与敌将碰撞；鬼戟同时命中敌兵。
6. 士兵收到原通用命中事件 65539；鬼戟可以继续穿过后续格。敌将通过 `Hurt → host 293 → 0x43ED96 → 65550` 接收 ATTACK 的直接伤害。这里的来源参数是 0，不应用施法者智力倍率，也不抽普通攻击伤害随机数。
7. 御飞刀先调用宿主 295，扣除 `120000 × 50 / 100 = 60000` 集气，最低为 0。受伤锁定阻止体力伤害，不阻止这次集气扣除。
8. 命中敌将后移除将领碰撞位。鬼戟仍保留敌兵碰撞位。普通飞行对象的淡出在后续一次源更新完成，鬼戟按 8 次源更新间隔逐级淡出，完整轨迹为 120 次更新。

## Web 实现与画面

- `native-magic-shoot.ts`：纯主协程、固定点飞行、碰撞分类、直接伤害及淡出函数。
- `battle-native-magic.ts`：源更新适配、真实单位受伤/伤亡、效果所有权和存档校验。
- `battle-unit-scheduler.ts`：在每次源单位更新旁推进该协程，避免一次性执行三帧技能后才更新三帧单位。
- `BattleView.tsx`：使用 13001–13007 原 SHP 资源绘制箭、飞刀、鬼戟及关联光效。所有资源在战前解码，镜头/缩放和暂停均不推进模拟状态。
- `convert_assets.py`：增加 11 个相关对象、32 张源帧；这些技能帧的 `#9999` 等待不再截成 128。保留原 OF_WHITELIGHT 标记，白光资源使用亮光合成，避免画出黑色矩形光晕。

画面的黑场/调色板使用 Canvas 合成适配，尚非 DirectDraw 调色板运算的逐像素验证。当前提供的是源飞行资源和共用光效层；所有命中粒子、飞行尾迹、声音和镜头子协程还没有全部执行。

## 仍需闭合的一比一差距

- 原全局混合对象链与脚本上下文的创建、插入和更新顺序。
- FlyLight、FireTail、HitGeneral、SmallFireBall 等子协程的完整对象调度与随机消耗，因此不能声称完整战斗 RNG 已经相同。
- LockCamera / MoveCamera 的完整相机轨迹，以及原调色板、混合和音频提交。
- 主将施法/受伤动作对原对象状态机的所有影响；其他技能的真实脚本仍有暂定执行器。
- 敌对电脑双方的完整实战、连续战役的同快照同决策回放。

不得用本轮主脚本和局部原码对照替代这些验收项，也不将全部 110 个技能标为完成。
