# 攻击动作与命中帧对照

新建战斗使用 `attackRules: native-actions-v1`，普通攻击和特殊攻击分别读取原包 `ATTACK`、`WIN` 动作。命中由模拟中的源更新时钟触发，Canvas 只读取保存的年龄选帧。**这完成了本轮攻击动作解析与时点的对照，不代表整个战场或游戏已一比一。**

## 原版证据

EXE SHA256：`1098558aaea96ae552753df786a8d3910df08fda11c8219dfa133ca001d8e419`。

PAK SHA256：`4db9aa8d7ecaedc61b2826c63e4e130bffaae0f3c36c0c34b20bc76bb7bc47e6`。

| 地址 | 核实的行为 |
|---|---|
| `0x436F4F` | 士兵资源的普通攻击读取 `ATTACK` 到偏移 32，特殊攻击读取 `WIN` 到偏移 48 |
| `0x43DDBF` 消息 65543 | 特殊标志选择动作 64，之后将对象的逻辑动作字段写回 4；普通攻击直接选择动作 4 |
| `0x421E1B` | TYPE_FORCE 的动作 64 使用特殊动作链；选择首节点时处理节点事件，并跳过零时长节点 |
| `0x436B9A` | 默认时长为 1；`#N` 同时修改前一节点和后续默认时长；`@%OM_ATTACK` 挂到前一节点；星号帧不加入链；`SCROVER` 截断循环 |
| `0x4374E4`、`0x468370` | 读取动作目录后补齐末尾路径分隔符，再解析帧名 |
| `0x421BF2` | 每次源更新递减当前帧计数；进入下一帧时处理其事件，链结束返回 -1 |
| `0x43D125`、`0x43E55C` | 单位决策选择攻击后，同次单位更新仍推进动作链 |

以现役兵为例（以下计数均为源更新次数）：

| 动作 | 旧 Web 命中时点 | 核实后的命中时点 | 原动作总时长 |
|---|---:|---:|---:|
| 朴刀普通攻击 | 18 | 15 | 30 |
| 弓兵远程攻击 | 15 | 12 | 35 |
| 弓兵近战特殊攻击 | 沿用普通攻击 | 15 | 30 |

弓兵远程动作的第 5 帧持续 8 次更新，事件在进入该帧时触发；旧转换将 `#8` 只作用于后一帧，同时将事件记到前一帧结束，因此画面和时点都偏移。特殊攻击读取不同的原始 SHP 帧，不能只改变冷却后继续播放普通射击。

## 可重跑的机器码对照

`../web-port-research/tools/native_attack_animation_oracle.py` 从指纹固定的 PAK 读取真实 CP950 `THINGS.INI`，执行原解析器、分配器、分词/整数解析、动作选择和逐帧推进函数。INI 文本/常量读取以及 SHP 指针查找由数据适配提供，原计时与事件代码没有替换，也不修改随机函数。

共验证 **266 个实际动作流、8,000 次帧推进**：52 个士兵普通动作、52 个士兵特殊动作、120 个主将身体动作、34 个武器动作、8 个主将坐骑动作。逐个核对帧名、节点时长、命中节点、每次更新选中的帧及结束时刻。当前这些攻击流均为正时长、有限链；有命中消息的动作各有一次消息。

验证器使用构造的 TYPE_FORCE 资源，将被测节点链放入动作槽，再调用原选择器和步进器；因此它证明真实动作文本的解析/推进语义，不声称逐个执行了所有主将、武器、投射物的完整对象回调。生成证据保存在 `evidence/ai/native-attack-animation-vectors.json`，副本在核心 `fixtures`。

## Web 接入与兼容

- `tools/native_animation.py` 单独解析已核实的攻击语法。未知消息/脚本和无限攻击链直接报错，避免静默丢事件。
- 转换器保留旧 `attack` 以及人物外观中旧攻击时间；额外输出 `sourceAttack`、`specialAttack` 和核心动作表。攻击动作子集增加 520 张源帧，校准时为 **227 个对象、5,746 张源帧**；随后加入普通投射物后，当前完整资源为 **231 个对象、5,789 张源帧**，见[远程弹道对照](NATIVE-PROJECTILE-PARITY-2026-11-18.md)。
- `native-attack-animation.ts` 按身体/兵种、现役/预备、蓝红双方与特殊标志查找动作。选帧函数同时供 Canvas 和机器码轨迹测试使用，直接接收整数源年龄。
- 调度器保存 `clock.attackEvent`。命中前后 JSON 恢复均保持事件进度；活动攻击的游标缺失、跳过或重复已到期事件会被存档校验拒绝。
- 无 `attackRules` 的旧战中快照继续使用旧图集动作、外观命中时间和 `hit` 标志；不在读档时补新规则。新建战斗或通过选将重建下一阵时启用新规则，匹配现有版本切换方式。
- 原版弓兵的近战特殊动作不等于近战兵特殊攻击的必中标志；保留此前核实的两种分支，不把所有特殊动作都变成必中。

## 验证结果

核心 **8,010 项 / 23 文件通过**，其中本轮新增 376 项：266 个原动作逐帧对照、104 个士兵普通/特殊事件集成案例、资源兼容，以及近远距离弓兵、保存恢复、旧规则和损坏游标测试。

浏览器 **31 场景通过**，包括桌面/手机满编 400 人交战及特殊动作、暂停不推进时钟、敌军入侵、战中存读档、轮战、6 种视口、24 组地形。类型检查及生产构建通过。渲染选帧复用调整后，376 项专项测试、完整浏览器回归、类型检查和构建再次通过。开发服务固定 `http://127.0.0.1:25369/`，HTTP 200。

实战截图：`screenshots/native-troops-combat-1440.png`、`screenshots/native-troops-combat-390.png`。桌面全屏、控制区与单位比例通过检查；手机竖屏完整显示队伍，但满编兵员仍较小，画面空间尚属适配。

## 未完成范围

全局对象链表调度、主将装备/速度、全部武将技和军师技仍未完整接入；普通四类远程投射物已经独立记录，但技能投射物还没有接入。主将连击以及防御、受伤、待命、行走、死亡等完整动作语义尚未本轮校准。攻击脚本中的声音位置已解析，但没有接入逐动作音效播放。原屏幕坐标、透视、十命令/五分队及战略层缺项仍需继续对照。

本轮已检索 Modern Web Guidance 的 Canvas 动画计时，没有适用原游戏动作解析的条目；浏览器测试采用 Playwright Expert 的页面对象与自动等待方式。
